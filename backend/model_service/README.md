# Модель дома как сервис

Своя модель (`jarvis-home`, Qwen2.5-1.5B, дообученная QLoRA — см.
`training/README.md`) отдаётся отдельным HTTP-сервисом с метриками. Джарвис
ходит к модели только через него.

```
Джарвис (агент) ──HTTP──▶ model_service :8090 ──▶ Ollama :11434 ──▶ jarvis-home-v6 (GGUF q8_0, RTX 2060)
                                │
                                ├── /metrics ◀── Prometheus :9090
                                └── /v1/model ── версия из реестра MLflow
```

## API

| | |
|---|---|
| `POST /v1/generate` | один шаг модели: системный промпт, история, инструменты → ответ и вызовы инструментов. Так ходит Джарвис (`app/llm/home_service.py`) |
| `POST /v1/command` | фраза → первый шаг модели (какие инструменты она вызовет) с промптом и инструментами Джарвиса — для `curl`, демо и нагрузочного теста |
| `GET /v1/model` | что отдаётся: модель Ollama, digest, квантизация, версия и алиас в реестре MLflow |
| `GET /v1/stats` | задержка (p50/p90/p95/p99) и ошибки с момента запуска, JSON |
| `GET /metrics` | то же для Prometheus |
| `GET /health` | 200, если модель есть в Ollama, иначе 503 |

Документация OpenAPI — `http://localhost:8090/docs`.

```bash
curl -X POST localhost:8090/v1/command -H "Content-Type: application/json" -d '{"text": "выключи свет на кухне"}'
# {"tool_calls": [{"name": "control_devices", "arguments": {"room": "кухня", "device": "light", "action": "off"}}],
#  "timing": {"total_ms": 377.3, "inference_ms": 359.2, "prompt_tokens": 1776, "completion_tokens": 34, "tokens_per_second": 102.1}, ...}
```

**Метрики Prometheus** (`home_model_*`): запросы по эндпоинту и исходу
(`ok` / `upstream_error`), гистограммы полного времени запроса и времени самой
модели, холодные старты (модель пришлось загружать в память), токены на входе и
выходе, токены в секунду, вызовы по инструментам, «битые» вызовы (невалидный
JSON внутри `<tool_call>` — парсер их отбрасывает), запросы в работе.

## Запуск

- **Как у Джарвиса:** `.env` → `HOME_LLM_SERVICE_URL=http://localhost:8090`,
  лаунчер `start_jarvis_voice.bat` сам поднимает `python -m model_service` без
  окна (лог — `backend/model_service.log`). Без этой строки Джарвис ходит в
  Ollama напрямую, как раньше. Сервис недоступен — дом обслуживает основная
  модель (Groq), как при выключенной видеокарте.
- **В контейнере:** `docker compose --profile model-service up -d --build`
  (образ 243 МБ: только `app/` и `model_service/`; модель остаётся в Ollama на
  хосте, на видеокарте). Вместо нативного, не вместе — оба на порту 8090.
- **Prometheus:** `docker compose --profile monitoring up -d` → http://localhost:9090.

Настройки (окружение, по умолчанию — `HOME_LLM_*` из `.env`):
`MODEL_SERVICE_MODEL`, `MODEL_SERVICE_OLLAMA_URL`, `MODEL_SERVICE_PORT`,
`MODEL_SERVICE_KEEP_ALIVE` (сколько Ollama держит модель в памяти; `-1` —
всегда, без холодных стартов, но 1,8 ГБ видеопамяти заняты постоянно).

## Качество через сервис

Экзамен (`training/evaluate.py`) умеет ходить через сервис —
`--model service:jarvis-home-v6`: та же модель тем же путём, что у Джарвиса,
целиком через агента и симуляцию дома. Баллы пишутся в MLflow как
`exam.service_*`.

| jarvis-home-v6, код от 05.10 | основной (103) | яркость (30) | новые функции (56) |
|---|---|---|---|
| напрямую в Ollama | 102 (99%) | — | — |
| **через сервис** | **102 (99%)** | **30 (100%)** | **56 (100%)** |

Напрямую и через сервис ответы совпали по каждому из 103 заданий: сервис ничего
не меняет в том, что видит модель (промпт в контейнере и нативно совпадает до
хеша). Общий промах — «какая влажность в столовой» (модель спросила историю, а
не текущее состояние).

## Скорость

`python -m model_service.loadtest` — фразы всех трёх экзаменов на `/v1/command`,
по 200 запросов на каждом уровне параллельности, после прогрева. RTX 2060 6 ГБ,
q8_0, рядом в видеопамяти голос Voicebox. 05.10.2026:

| одновременно | p50 | p90 | p95 | p99 | запросов/с | ошибки |
|---|---|---|---|---|---|---|
| 1 | 351 мс | 453 мс | 718 мс | 1032 мс | 2.80 | 0 |
| 2 | 639 мс | 1057 мс | 1111 мс | 1399 мс | 2.86 | 0 |
| 4 | 1313 мс | 1773 мс | 2023 мс | 2333 мс | 2.86 | 0 |

- Пропускная способность не растёт с параллельностью (~2,85 запроса/с): Ollama
  на одной видеокарте считает запросы по одному, остальные ждут в очереди — и
  задержка растёт пропорционально. Для дома, где команды идут по одной, это
  p50 350 мс; больше — либо `OLLAMA_NUM_PARALLEL` (дороже по видеопамяти под
  кэш), либо вторая видеокарта.
- Промпт — ~1770 токенов (описания шести инструментов), ответ — 15–35 токенов,
  генерация ~100 токенов/с. Ollama переиспользует кэш общего начала промпта, так
  что основное время — генерация вызова.
- Холодный старт (модель выгружена после 5 минут простоя) — +3 с на первый
  запрос; метрика `home_model_cold_starts_total`.

Отчёт — `model_service/results/loadtest_*.json`, он же и цифры
(`serving.c<N>.*`) — в запуске версии в MLflow.
