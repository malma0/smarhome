# Jarvis backend (фаза 0-1: ядро ИИ + десктопный голос)

Backend ИИ-ассистента умного дома. Полное ТЗ — в [docs/TZ.md](docs/TZ.md);
этот README покрывает то, что реально реализовано на данный момент: **ядро,
не привязанное ни к конкретной LLM, ни к какому-либо устройству** (фаза 0),
плюс десктопное голосовое приложение для разработки (фаза 1). Home Assistant
не нужен вообще — ни одного доменного тула ещё не зарегистрировано.

## Архитектура

```
Жилец (голос / iPad)                                    <- пока не реализовано
        │
        ▼
Voice-agent платформа                                    <- пока не реализовано
   STT → [ Jarvis backend ] → TTS
        │
        ▼
┌──────────────────────────────────────────────────────────┐
│ Jarvis backend                                             │
│                                                              │
│  Ядро (device-agnostic И llm-agnostic)         <- ЭТО ЕСТЬ  │
│   ├── цикл tool use через LLMProvider-адаптер               │
│   │     (llm/claude.py, llm/groq.py, llm/ollama.py —        │
│   │      см. разделы про провайдеров ниже)                  │
│   ├── ToolRegistry — пуст, ждёт доменных тулов              │
│   ├── персона: butler / warm / adaptive                     │
│   └── память: SQLite (настройки дома + предпочтения          │
│         по resident_id)                                      │
│                                                              │
│  Реестр доменных тулов                     <- пока пустой   │
│  Слой внимания                             <- пока не реализовано │
└──────────────────────────────────────────────────────────┘
        │
        ▼
Home Assistant → появится в фазе 1, когда зарегистрируется первый домен
```

Ключевой принцип (см. [docs/TZ.md §4](docs/TZ.md)): ядро гоняет цикл tool use
над реестром тулов и над LLM-провайдером, которые ему подставляют снаружи —
сегодня реестр пуст, завтра туда добавляется домен `light`, и ядро не
меняется ни строчкой; то же верно и для смены LLM-провайдера.

Jarvis отвечает на любые вопросы, не только про дом — это часть ядра, а не
следствие наличия домашних тулов: пустой `ToolRegistry` тому доказательство
(см. тесты в `test_agent.py`).

```
    wake_word.py                 # локальная проверка имени «Джарвис» (Vosk)

    voice_ui.py                  # события голосового цикла — для окна и терминала

      base.py                     # TTSProvider protocol — тот же паттерн, что и LLMProvider
      edge.py                     # EdgeTTSProvider — бесплатные нейро-голоса Microsoft, дефолт
      piper.py                     # PiperTTSProvider — открытая модель, офлайн, ниже качеством
      sapi.py                        # SapiTTSProvider — офлайн Windows-голоса, аварийный фолбэк
      elevenlabs.py                   # ElevenLabsTTSProvider — лучшее качество, free tier не даёт API
      voicebox.py                      # VoiceboxTTSProvider — клонированный голос, локально, бесплатно

      text.py                          # чистка разметки/эмодзи перед озвучкой
      playback.py                      # громкость ответа для анимации кружка
    agent.py                     # JarvisAgent — сам цикл tool use

  static/voice.html             # браузерный STT/TTS демо, устарело — см. voice_app.py
  jarvis_gui.py                  # окно Jarvis (кружок + переписка) — основной способ говорить
  gui/                           # HTML/CSS/JS окна; index.html?demo — демо без Python
  voice_app.py                   # голосовой цикл (Whisper + TTS) и его терминальная версия
  voices/                        # скачанные модели Piper (.onnx), не в git — см. инструкцию ниже
  chat_cli.py                   # локальный текстовый REPL без HTTP
  tests/                        # test_llm_claude/groq/ollama, test_tts_piper/edge/sapi/elevenlabs/voicebox,
                                 # test_registry, test_domain_computer/files, test_memory, test_persona,
                                 # test_agent, test_main, test_voice_app

```

## Как поднять локально

Home Assistant не нужен — только Claude API ключ.

1. **Секреты.** Скопируйте `.env.example` в `.env` в корне репозитория и
   заполните `ANTHROPIC_API_KEY`.

2. **Зависимости backend:**

   ```bash
   cd backend
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   ```

3. **Запуск:**

   ```bash
   uvicorn app.main:app --reload --port 8000
   ```

   или для быстрой ручной проверки без HTTP:

   ```bash
   python chat_cli.py
   ```

4. **Пример запроса** (`resident_id` — заглушка вместо голосовой идентификации,
   см. [docs/TZ.md §5](docs/TZ.md)):

   ```bash
   curl -X POST http://localhost:8000/chat \
     -H "Content-Type: application/json" \
     -d '{"session_id": "test", "resident_id": "ivan", "message": "какая столица Франции?"}'
   ```

   Ответ: `{"response": "Париж.", "actions": []}` — `actions` пуст, потому что
   ни одного тула ещё не зарегистрировано; это ожидаемо для фазы 0.

5. **Настройки дома** (персона/проактивность — до появления iPad-приложения):

   ```bash
   curl -X PUT http://localhost:8000/settings \
     -H "Content-Type: application/json" \
     -d '{"persona_mode": "butler"}'
   ```

6. **Скачать голос для озвучки (один раз):**

   ```bash
   mkdir voices
   curl -sL -o voices/ru_RU-irina-medium.onnx "https://huggingface.co/rhasspy/piper-voices/resolve/main/ru/ru_RU/irina/medium/ru_RU-irina-medium.onnx"
   curl -sL -o voices/ru_RU-irina-medium.onnx.json "https://huggingface.co/rhasspy/piper-voices/resolve/main/ru/ru_RU/irina/medium/ru_RU-irina-medium.onnx.json"
   ```

   ~63 МБ, полностью открытая модель ([Piper](https://github.com/OHF-voice/piper1-gpl),
   голос "irina", женский). `backend/voices/` не коммитится в git — каждый
   скачивает себе сам.

7. **Поговорить голосом — окно Jarvis (фаза 1, основной способ):**

   Двойной клик по `start_jarvis_voice.bat` (или ярлык на рабочем столе):
   батник поднимает Voicebox и открывает окно Jarvis, консоль не остаётся.
   Вручную: `.venv\Scripts\pythonw.exe jarvis_gui.py`.

   Окно (`jarvis_gui.py` + `backend/gui/`) — нативное окно через
   `pywebview` и движок WebView2, встроенный в Windows 11 (отдельный
   браузер не нужен):
   - **кружок** в центре показывает, что происходит: тусклый и медленно
     «дышит» — спит; голубой и реагирует на голос — слушает; фиолетовый,
     переливается — думает; розовый и пульсирует **в такт настоящему
     голосу** Jarvis — говорит (громкость ответа считается перед
     проигрыванием, `app/tts/playback.py`). Пока Voicebox ~25 с готовит
     голос, кружок показывает «Готовлю голос…», а не пульсирует в тишине;
   - **клик по кружку** — разбудить, как если сказать «Джарвис»;
   - **переписка**: реплики и ответы, под ответом — что Jarvis сделал
     («Открыл notepad», красным — если не вышло);
   - **✎ исправить** под любой своей голосовой фразой — исправление уходит
     в датасет для обучения;
   - **кто говорил** — имя под каждой голосовой фразой (пунктиром, если
     Jarvis не уверен). Клик — «Это Матвей / Это Эля / другой»: запись в
     датасете переподписывается, а если образец голоса уже ушёл не тому
     человеку — аудио переезжает в правильную папку и оба профиля
     перестраиваются. Так обычные диалоги копят **правильно подписанные**
     записи голосов для дообучения;
   - **поле внизу** — написать Jarvis текстом;
   - сверху — кто говорит (по голосу) и сколько данных накоплено;
   - **клик по имени сверху — «Голоса в доме»**: список известных голосов,
     «Дозаписать» и «Записать голос» для нового человека — прочитать вслух
     три фразы с экрана, каждый кусок ~4 с речи становится образцом голоса
     (эти фразы не уходят ни в Whisper, ни в датасет). Так добавляется
     второй жилец, не дожидаясь случайного «Как тебя зовут?»;
   - незнакомый голос в длинной фразе — окошко «Как тебя зовут?» с
     кнопками уже известных голосов.

   С двумя и больше голосами Jarvis различает людей и тогда, когда никто не
   дотягивает до порога: если фраза явно ближе к одному (≥ 0.45 и на 0.10
   выше второго) — это он, но профиль такая «догадка» не учит. На реальных
   данных короткая фраза набрала 0.60 к своему (мужскому) голосу и
   0.28–0.45 к женским.

   Вывод окна (ошибки и т.п.) — в `backend/jarvis_gui.log`. Дизайн можно
   посмотреть без Python: открыть `backend/gui/index.html?demo` через
   любой локальный веб-сервер — там сценарий-демо.

   Терминальная версия осталась: `start_jarvis_voice.bat terminal` или
   `.venv\Scripts\python.exe voice_app.py`. Оба варианта — один и тот же
   код Jarvis: голосовой цикл сообщает события через `app/voice_ui.py`, а
   терминал и окно просто по-разному их показывают.

   Нужен `GROQ_API_KEY` в `.env` (используется для распознавания речи через
   Whisper, независимо от того, какой `LLM_PROVIDER` отвечает на сам вопрос).
   Никаких новых аккаунтов, всё бесплатно.

   **Режим без рук (по умолчанию, `VOICE_MODE=wake`)** — никаких клавиш,
   Jarvis отзывается на имя (`app/wake_word.py`, `app/hands_free.py`):
   - «Джарвис, включи свет» — сразу выполняет;
   - просто «Джарвис» — короткий сигнал, дальше 8 с слушает команду без имени;
   - после ответа ещё 10 с слушает продолжение без имени (диалог), потом
     снова «спит»;
   - пока имя не прозвучало, каждая фраза проверяется **только локально**
     (Vosk, маленькая русская модель) и выбрасывается — в интернет ничего
     не уходит и не сохраняется;
   - пока Jarvis думает и отвечает, микрофон не слушает — чтобы не принять
     собственный голос за новую фразу.

   Почему распознавание всем словарём, а не «одно слово»: проверено на
   тестовом наборе — с грамматикой из одного слова Vosk ловил имя везде,
   но и срабатывал на «Джордж», «жарко», «Чарли», «джинсы»; всем словарём —
   ноль ложных срабатываний. Мужской тестовый голос модель слышит как
   «джервис» — это тоже слово её словаря, поэтому оба считаются именем.
   Фразы нарезаются по паузам детектором речи WebRTC; проверено на
   склейке реальных записей с фоновым шумом до −47 дБ.

   Нужна модель Vosk (один раз, 46 МБ):

   ```bash
   curl -L -o models/vosk-model-small-ru-0.22.zip https://alphacephei.com/vosk/models/vosk-model-small-ru-0.22.zip
   ```

   и распаковать в `backend/models/` (папка не в git). Если Vosk или модели
   нет — Jarvis сам переключается в режим с Enter.

   **Режим с Enter (`VOICE_MODE=push`)**: Enter — начнётся запись, скажите
   что-нибудь, Enter ещё раз — запись остановится, Jarvis распознает речь,
   ответит и озвучит ответ.

   **Качество распознавания речи — без всякого обучения** (`app/audio_capture.py`):
   - Микрофон открыт весь сеанс, последние 0.5 с звука всегда держатся в
     памяти (ничего не сохраняется, пока не нажат Enter). Раньше микрофон
     открывался только после Enter, а открытие на этом ноутбуке измерено —
     0.72 с: первое слово фразы регулярно терялось («Включи на нём видео» →
     «На нём видео»). Плюс 0.3 с записи после второго Enter — для
     последнего слова. Пока приложение запущено, Windows показывает значок
     «микрофон используется» — это оно.
   - Тишина в Whisper не отправляется: проверено вживую, на лёгком фоновом
     шуме он «слышит» «Спасибо.» или «Дисклеймер», а его собственная оценка
     «здесь нет речи» у Groq всегда 0. Перед отправкой запись проверяет
     детектор речи WebRTC (`webrtcvad`, режим 2 — подобран на реальных
     записях: фоновый шум ≈0.1 с «речи» из 2 с, тихая речь на −50 дБ ≈8 с
     из 10).
   - Если шум всё же прошёл детектор, Whisper «слышит» концовки субтитров,
     на которых учился: «Продолжение следует...», «Субтитры сделал
     DimaTorzok», «Спасибо за просмотр» (`app/transcript_filter.py`). Такие
     фразы отбрасываются — без ответа и без записи в датасет. «Спасибо.»
     не фильтруется: это нормальная фраза для Jarvis.
   - Whisper получает подсказку со словарём: встроенный список (Джарвис,
     YouTube, Майнкрафт...), свои слова из `WHISPER_VOCABULARY` в `.env` и
     имена всех жильцов.

   **Запись датасета для будущего обучения** (`app/dataset.py`): каждая фраза
   сохраняется в `backend/dataset/` — аудио, что распознал Whisper, и ответ
   Jarvis. Если Whisper ошибся — вместо простого Enter впиши, что на самом
   деле сказал, и нажми Enter: исправление сохранится к последней фразе.
   Формат совместим с `load_dataset("audiofolder", ...)` из Hugging Face —
   готов для дообучения Whisper без конвертации. Это твой голос, то есть
   личные данные: папка в `.gitignore` и никуда с компьютера не уходит.
   При запуске Jarvis показывает, сколько уже накоплено. У каждой фразы
   записано, кто говорил и насколько уверенно это определено
   (`speaker_how`: `confident` / `closer` / `last` / `asked` / `unknown` /
   `corrected`, `speaker_score`), и путь к образцу голоса, если фраза его
   пополнила. Для обучения распознавания голосов надёжны `confident`,
   `asked` и `corrected`; остальные — догадки.

   **Определение говорящего по голосу** (`app/speaker_id.py`) работает поверх
   введённого имени, а не вместо него: при первой фразе от незнакомого
   голоса Jarvis спросит имя один раз и запомнит голос (Enter — не
   запоминать), а дальше при каждой отдельной фразе заново пытается узнать
   говорящего — если голос сменился (например, ответил кто-то другой), имя
   тоже поменяется автоматически, без повторного ввода. Работает полностью
   локально и офлайн через [Resemblyzer](https://github.com/resemble-ai/Resemblyzer)
   (сравнение голосовых эмбеддингов, не имеет отношения к распознаванию речи
   выше) — проверено на реальных образцах: одна и та же личность (голос
   Ханны и клонированный из него голос Джарвиса) даёт сходство ~0.86, два
   разных голоса (Ханна и синтезированный мужской) — ~0.53. `VOICE_ID_ENABLED=false`
   в `.env` отключает это полностью, оставляя только ручной ввод имени, как
   раньше.

   **Модель по умолчанию — ECAPA** (SpeechBrain, `SPEAKER_MODEL=ecapa`,
   ~89 МБ, скачивается в `backend/models/` при первом запуске, лицензия
   Apache-2.0). Сравнение на коротких кусках пяти голосов (наши реальные
   записи, два чтеца аудиокниг, два синтетических голоса): на 1 с речи
   ECAPA угадывает верно 100% против 91% у Resemblyzer, а «свой»/«чужой»
   разделяются намного лучше (5%/95%: 0.44/0.31 против полностью
   перекрытых 0.58/0.67). Ещё не проверено на нескольких **мужских**
   голосах рядом — это нужно сделать на реальных записях семьи. У каждой
   модели свои пороги (ECAPA 0.50) и свои профили; смена модели —
   `python tools/voice_profiles.py rebuild --model ...` (перестраивает
   профили из сохранённого аудио).

   **Аудио каждого образца голоса сохраняется** в `backend/voiceprints/`
   (не в git — личные данные): из него перестраиваются профили под новую
   модель, и это размеченные данные для обучения своей модели под семью
   (следующий шаг, когда у каждого наберётся хотя бы пара минут записей).

   Ниже — цифры для прежней модели Resemblyzer.

   На **реальном** микрофоне ноутбука картина хуже, чем на чистых
   записях: длинные фразы (~4 с речи) похожи на свой же профиль на
   0.73–0.78, чужие голоса — максимум 0.56, а короткие команды (~1 с речи)
   на свой же голос — всего 0.54–0.60. Поэтому:
   - порог `VOICE_ID_THRESHOLD=0.70` (было 0.75 — внутри реального
     диапазона «тот же человек»);
   - короткие фразы (меньше 1.5 с речи) могут совпасть, но профиль не
     учат и **не спрашивают** «как тебя зовут?» — без совпадения считается,
     что говорит тот же, кто говорил последним;
   - если голос не узнан в длинной фразе — вопрос с кнопками уже известных
     голосов («Это Матвей»): ответить тем же именем (в любом регистре) =
     добавить запись к своему голосу, узнавание станет увереннее.

   Профиль каждого жильца — не одна запись, а набор из нескольких последних
   (до 5) — совпадение с любой одной из них засчитывается, поэтому одна
   короткая/шумная фраза при знакомстве не решает всё. Каждое уверенное
   распознавание длинной фразы в дальнейшем тоже добавляется в профиль как
   новый образец — узнавание со временем становится надёжнее само по себе.

   Требует отдельной установки (см. комментарий в `requirements.txt`) —
   `webrtcvad` (зависимость Resemblyzer) не имеет готового wheel под Windows
   и требует компилятор C++ для сборки из исходников, поэтому используется
   форк с готовыми wheel'ами и `resemblyzer` ставится отдельно с `--no-deps`:

   ```bash
   pip install -r requirements.txt
   pip install --no-deps resemblyzer
   ```

   `JARVIS_TTS_ENABLED=false` в `.env` — отключает озвучку полностью, Jarvis
   отвечает только текстом (распознавание речи всё равно работает). Удобно,
   когда тестируете именно tool use и не хотите каждый раз ждать синтез речи.

   **Голос озвучки — сменный** (`app/tts/`, тот же паттерн, что и у LLM):
   - `TTS_PROVIDER=edge` (по умолчанию) — бесплатные нейро-голоса Microsoft
     Edge (`edge-tts`, без ключа/аккаунта), заметно лучше по качеству, чем
     офлайн-варианты. Минус: облачный сервис (не открытый исходный код,
     реверс-инжиниринг не публичного API), нужен интернет, изредка бывает
     медленный/неудачный запрос — тогда срабатывает таймаут (15с) и
     автоматический откат на `sapi`. Голос по умолчанию —
     `ru-RU-SvetlanaNeural` (женский), есть также `ru-RU-DmitryNeural`
     (мужской) — меняется `EDGE_TTS_VOICE`.
   - `TTS_PROVIDER=piper` — полностью открытая (не Microsoft, не облако)
     нейросетевая модель, работает целиком офлайн, без сети — но для
     русского всего 4 голоса (`irina` женский, `denis`/`dmitri`/`ruslan`
     мужские), заметно ниже качеством, чем `edge`. Модель — отдельный файл
     ~63 МБ, скачивается один раз (см. ниже), не коммитится в git.
   - `TTS_PROVIDER=sapi` — офлайн-голоса Windows (pyttsx3), самое низкое
     качество ("роботический" голос) — используется автоматически как
     аварийный фолбэк, если основной провайдер не смог даже запуститься
     или ответить.
   - `TTS_PROVIDER=elevenlabs` — по качеству и выбору голосов на порядок
     выше всех остальных (тысячи голосов в библиотеке), но **важная
     оговорка, выясненная опытным путём, а не из документации**: на
     бесплатном тарифе ElevenLabs API **не даёт использовать вообще ни один
     готовый голос** — ни из библиотеки, ни встроенный в аккаунт по
     умолчанию (`402 Payment Required: paid_plan_required`). Через API на
     бесплатном тарифе работает только голос, который вы сами клонировали
     (Instant Voice Clone, до 3 штук бесплатно — но и это в итоге тоже
     показывало платный экран), либо нужна платная подписка (от $5/мес).
     Провайдер (`app/tts/elevenlabs.py`) написан и протестирован на моках,
     но проверить его на реальном голосе бесплатно не вышло — честно
     фиксируем это здесь, чтобы не наступать на те же грабли дважды.

   - `TTS_PROVIDER=voicebox` — клонированный голос через
     [Voicebox](https://github.com/jamiepine/voicebox) + модель Chatterbox
     Multilingual (Resemble AI): единственный вариант здесь, который не
     завязан ни на какого облачного вендора и не имеет free-tier ограничений
     ElevenLabs — голос клонируется локально из короткого (~30с) образца
     реальной речи на нужном языке (кросс-языковое клонирование даёт
     заметный акцент — проверено на практике, не рекомендуется) и дальше
     генерируется полностью на этой машине. Требования:
     - отдельно запущенный `voicebox-server.exe` (из его собственной папки
       установки, не из этого репозитория — иначе он насоздаёт `data/`
       прямо в репо) — порт по умолчанию (8000) совпадает с `JARVIS_PORT`,
       одновременно не запускать;
     - голосовой профиль: имя в `VOICEBOX_PROFILE`, образец голоса (WAV,
       10–30 с чистой речи без музыки) в `VOICEBOX_REFERENCE_WAV`, рядом
       с ним — расшифровка в `.txt` с тем же именем (`voice.wav` →
       `voice.txt`, Voicebox требует текст к каждому образцу). Если в
       запущенном Voicebox такого профиля нет, Jarvis создаёт его сам из
       этого файла при первой озвучке — голос определяется файлом в
       `voice_reference/`, а не только базой Voicebox (которая может
       оказаться другой: свежая установка, или Voicebox, запущенный из
       песочницы Claude, получает свою копию app-data). Сама папка
       `voice_reference/` в git не попадает.
     - **образец должен быть чистым**: Chatterbox копирует его целиком,
       вместе с шумом. Образец ReyZi из видео с YouTube (гул ниже 200 Гц
       почти как её голос, шипение выше 8 кГц, звук на −53 дБ) давал
       ответы с гулом и вдохами. Очистка образца и ответа
       (`app/tts/cleanup.py`, `VOICEBOX_CLEANUP=true`) заметно помогла, но
       на слух всё равно проиграла голосу из аудиокниги (Ханна, LibriVox:
       шум на 36 дБ тише речи против 15–20 у ReyZi). Сейчас голос — Ханна;
       для чистого образца очистка выключена, ей там нечего чинить;
     - **скорость речи** — `VOICEBOX_TEMPO` (у Ханны стоит 1.2: читает
       в темпе аудиокниги). Ответ ускоряется без повышения голоса
       (`app/tts/tempo.py`, WSOLA, ~0.1 с на ответ). У Voicebox своей
       настройки скорости нет. Последнее предложение («Что-нибудь ещё?»)
       может идти со своей скоростью — `VOICEBOX_ENDING_TEMPO` (стоит 1.1:
       на одной скорости начало тянулось, а концовка уже торопилась). Ответ
       генерируется целиком, поэтому стык ищется в паузе рядом с местом,
       где по длине текста начинается последнее предложение; нет паузы —
       весь ответ на одной скорости.

     Минус — скорость. На этом ноутбуке (Core Ultra 9 185H, без GPU)
     генерация примерно в 10 раз медленнее самой речи: «Включаю свет.» —
     ~25 с, две фразы — ~45 с. Что уже сделано, чтобы было не хуже:
     - **приоритет процесса** — Voicebox работает без окна, Windows
       считает его фоновым и отправляет на медленные ядра гибридного
       процессора: при обычном приоритете та же фраза шла ~170 с. Батник
       ставит High (ограничение потоков PyTorch до 6 не помогло; «выше
       среднего» — 30 с против 25 с у High);
     - **короткие ответы** — когда ответ озвучивается, Jarvis отвечает 1–2
       фразами без разметки (тот же вопрос: 1672 → 235 символов);
     - **прогрев** — при запуске Jarvis в фоне загружает модель (~3 ГБ),
       чтобы первый ответ не ждал её загрузку;
     - проверен альтернативный движок Qwen TTS: быстрее (20 с против 25),
       но по-русски говорит плохо («Включаю свет.» → «Спросив.») — отказ.

     Реально быстро будет только на видеокарте (RTX 2060 на другом ПК —
     ~1.5× от длины речи): Voicebox можно запустить там и указать его
     адрес в `VOICEBOX_BASE_URL`.

     **Ударения** (`app/tts/stress.py`): Chatterbox обучен на русском тексте
     с расставленными ударениями (знак U+0301 есть в его словаре), но в
     сборке Voicebox модуля расстановки нет — в логе «russian_text_stresser
     not available», отсюда неправильные ударения. Jarvis расставляет их
     сам перед отправкой — через ruaccent (MIT; оригинальный модуль —
     AGPL, для продаваемого продукта не годится). Омографы различает:
     «на двери висит замо́к» / «старинный за́мок». Модели (~195 МБ)
     скачиваются в `backend/models/ruaccent` при первом запуске.

     Как и все остальные провайдеры, при ошибке (сервер не запущен,
     генерация не удалась) автоматически откатывается на `sapi`.

   Живая проверка (не моки): синтезированные фразы (Piper, Edge и клонированный
   голос через Voicebox) гонялись обратно через настоящий Whisper (Groq) и
   распознавались практически без ошибок — STT и все TTS реально работают,
   не только собираются без ошибок. Само проигрывание через колонки я
   подтвердить не могу (не слышу) — это на вашей стороне.

8. **Поговорить голосом — браузерный демо (устарело, только для Chrome/Edge):**
   с запущенным `uvicorn` откройте `http://localhost:8000/voice`. Не
   работает в Firefox (там нет распознавания речи) и не задумано как
   постоянное решение — оставлено как альтернатива, если по какой-то причине
   десктопное приложение недоступно.

Ни то, ни другое — не настоящий голосовой пайплайн дома (см. фазу 9 в
[docs/TZ.md](docs/TZ.md)), это способ разговаривать с уже готовым мозгом
Jarvis уже сейчас, на компьютере.

## Альтернатива Claude: бесплатный провайдер без карты (Groq)

`LLM_PROVIDER=groq` в `.env` переключает ядро на [Groq](https://console.groq.com/keys) —
бесплатный тариф без привязки карты (14 400 запросов/день), крутит открытые
модели (`openai/gpt-oss-120b` по умолчанию) на своём железе — GPU не нужен.
Веса моделей открытые, поэтому нет привязки к одному закрытому провайдеру:
при желании те же веса можно позже поднять у себя.

```
LLM_PROVIDER=groq
GROQ_API_KEY=gsk_...
GROQ_MODEL=openai/gpt-oss-120b
```

**Честно про качество**: заметно надёжнее, чем локальная модель через Ollama
(ниже) — в ручной проверке 3 из 3 одинаковых команд ("включи свет в спальне")
дали идентичный корректный вызов тула, без пропущенных или лишних полей.
Не идентично Claude, но для разработки и тестов вполне рабочий бесплатный
вариант.

## Локальный self-hosted провайдер без интернета (Ollama)

`LLM_PROVIDER=ollama` в `.env` переключает ядро на бесплатную, полностью
локальную модель через [Ollama](https://ollama.com) — без единого платного
API-вызова. Проверялось на этой машине (без GPU, только CPU) с
`qwen2.5:1.5b`:

```bash
# один раз: ollama pull qwen2.5:1.5b, дальше служба Ollama работает в фоне
```

```
LLM_PROVIDER=ollama
OLLAMA_MODEL=qwen2.5:1.5b
OLLAMA_BASE_URL=http://localhost:11434
```

**Честно про качество**: на общих вопросах работает нормально ("какая
столица Франции?" → "Paris."), но **на tool use ощутимо менее надёжна**, чем
Claude — в ручной проверке одна и та же команда ("включи свет в спальне") на
одном прогоне пропустила обязательный параметр `on`, на другом добавила
несуществующее поле `object`, которого нет в схеме тула. Это ожидаемо для
модели такого размера на CPU, не баг адаптера. Использовать это стоит как
доказательство, что ядро реально llm-agnostic (не привязано к Claude), а не
как замену для реальных сценариев управления домом — тем более что
tool-use-домены (фаза 2+) как раз про надёжное управление реальными
устройствами/компьютером.

## Как гонять тесты

```bash
cd backend
pytest
```

Все тесты изолированы от внешнего мира — ни разу не идут в сеть и не трогают
рабочую БД:
- `test_llm_claude.py` — `ClaudeProvider` мокает HTTP-вызов `AsyncAnthropic`,
  проверяет только перевод схем/content-блоков в обе стороны.
- `test_llm_ollama.py` — `OllamaProvider` мокает HTTP-вызов к Ollama, включая
  перевод истории сообщений в OpenAI-стиль (tool_calls/role:"tool"), которого
  `ClaudeProvider` не требует, — реальный Ollama для CI не нужен.
- `test_llm_groq.py` — `GroqProvider` мокает HTTP-вызов к Groq; отдельно
  проверяет, что аргументы тула кодируются/декодируются как JSON-строка
  (в отличие от Ollama, где это уже был dict) — реальный ключ для CI не нужен.
- `test_registry.py` — `ToolRegistry` тестируется на фейковом `echo`-туле, без
  единого упоминания Home Assistant.
- `test_memory.py`, `test_persona.py` — работают на временной SQLite
  (`tmp_path`), не на `backend/jarvis.db`.
- `test_agent.py` — `JarvisAgent` тестируется через `FakeLLM` (не наследует
  ничего от Anthropic) и либо пустой, либо однотуловый `ToolRegistry`.
- `test_main.py` — `TestClient` проверяет `/health` и `/voice` (не `/chat` —
  это потребовало бы реального или тяжело замоканного вызова LLM).
- `test_voice_app.py` — только чистые/HTTP-части (`frames_to_wav_bytes`,
  `transcribe`); реальная запись с микрофона нуждается в живом устройстве,
  проверена вручную (см. раздел про десктопное приложение выше).

Ключи и запущенный Home Assistant для `pytest` не нужны — только для
реального end-to-end прогона через `uvicorn`/`chat_cli.py`.

## Что реализовано

**Фаза 0 (ядро):**
- [x] `LLMProvider`-адаптер: ядро не импортирует `anthropic` напрямую нигде,
      кроме `llm/claude.py`.
- [x] Три провайдера (`llm/claude.py`, `llm/groq.py`, `llm/ollama.py`)
      подключены без единого изменения в `agent.py` — подтверждает, что
      адаптер сделан правильно. Groq (открытые модели на их железе) заметно
      надёжнее на tool use, чем Ollama (маленькая модель на CPU).
- [x] Device-agnostic `ToolRegistry`: цикл tool use работает и с нулём
      зарегистрированных тулов.
- [x] Персона: 3 режима, `adaptive` — реальный (пусть и эвристический v1)
      компонент, обновляющий сигналы стиля по `resident_id`, а не просто
      статический пресет.
- [x] Персистентная память (SQLite): настройки дома + предпочтения жильца.
- [x] `POST /chat` → `{response, actions}`, `GET/PUT /settings`.
- [x] Jarvis отвечает на общие вопросы без единого домашнего тула.

**Фаза 1 (десктопный голос):**
- [x] `voice_app.py` — STT через Whisper (Groq, бесплатно) + сменный
      `TTSProvider` (`edge`/`piper`/`sapi`/`elevenlabs`/`voicebox`).

**Фаза 2 (управление компьютером):**
- [x] `open_application` (`app/domains/computer.py`) — небольшой быстрый
      allowlist (блокнот, калькулятор, paint, проводник) плюс общий поиск
      **среди всех установленных программ** через `Get-StartApps` (то же,
      что видит поиск в меню Пуск) — так открывается что угодно вплоть до
      Steam/Discord/Blender, без хардкода путей под каждую программу.
      Доступ к shell/терминалу заблокирован в обоих путях по ключевым
      словам (`cmd`, `powershell`, `bash`, `wsl`, `terminal`...) — это
      реально нужно, `Get-StartApps` перечисляет и "Developer PowerShell
      for VS 2022", и "Git Bash", если бы их не блокировать явно, общий
      поиск случайно открыл бы именно то, что было закрыто с самого
      начала. Проверено вживую: "открой Steam" реально запускает Steam
      (подтверждено по PID процесса), "открой powershell" отклоняется
      кодом с понятной ошибкой. Для браузера можно
      передать конкретный сайт (`url`, только `http`/`https` — `file:`,
      `mailto:` и т.п. отклоняются); без сайта запускается сам браузер по
      умолчанию (находится через реестр Windows) без адреса — открывается
      его собственная стартовая страница, а не что-то навязанное нами.
      Раньше "открой браузер" жёстко вёл на Google, даже если у жильца
      своя стартовая страница (обнаружено и исправлено после живой
      проверки на LibreWolf). Проверено вживую: "открой калькулятор"
      запускает `calc.exe`, "запусти в браузере YouTube" открывает именно
      `youtube.com`, просто "открой браузер" запускает реальный дефолтный
      браузер (LibreWolf) на его собственной странице, "открой терминал"
      модель отклоняет сама, ещё до попытки вызова тула.
- [x] `list_directory`/`read_file`/`write_file`/`delete_file`
      (`app/domains/files.py`) — доступ ко всей файловой системе (осознанный
      выбор пользователя, без песочницы), но перезапись/удаление и второй
      файл за один ход требуют `confirmed=true`, а системные папки Windows
      (`C:\Windows`, `Program Files` и т.п.) защищены безусловно, даже с
      подтверждением. Проверено вживую: перезапись без подтверждения
      отклонена моделью до вызова тула, с подтверждением — прошла; попытка
      удалить `hosts` с "я подтверждаю" в том же сообщении отклонена моделью
      полностью, до нашего кода-предохранителя дело не дошло.

## Что сознательно отложено

Со ссылкой на [docs/TZ.md §8](docs/TZ.md) — следующие фазы:

- **Фаза 1–6: домены умного дома** (`light`/`switch` → `cover` → `climate` →
  медиа/техника → энергетика/участок → безопасность/доступ) — регистрируются
  в уже готовый `ToolRegistry` по одному, от простого к самому рискованному.
  Старый climate-прототип (`app/tools.py`, `app/prompts.py` — удалены этим
  коммитом) переезжает в фазу 3 в новом виде, поверх реестра.
- **Слой внимания** — стартует, когда доменов/датчиков достаточно, чтобы
  было что комментировать проактивно.
- **Голосовой пайплайн и iPad-приложение** — backend спроектирован как
  чёрный ящик `текст → {response, actions}`, к которому они подключатся
  без изменений в ядре.
- **Выбор финальной LLM** — открытый пункт ([docs/TZ.md §9](docs/TZ.md));
  Claude — дефолт на время разработки, смена не требует переписывания ядра.
